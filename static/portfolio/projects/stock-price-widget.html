Stock Price Widget

어떤 웹페이지 위에서든 주식·코인 시세를 실시간으로 띄우는 위젯 오버레이입니다. 위젯 아래 페이지는 그대로 클릭되고, 우클릭 한 번으로 직접 만든 캔들 차트가 열립니다.

스토어 평점 5.0 운영 중 자체 캔들 차트 엔진 캐시·프리페치로 전환 지연 0 국내·해외주식·코인
Chrome 웹스토어 ↗
Why

왜 만들었나

주식·코인 시세가 수시로 궁금한데, 확인하려면 그때마다 보던 화면을 벗어나 증권사 앱이나 거래소 탭을 따로 열어야 했습니다. 돌아오면 하던 일의 맥락이 끊겨 있었습니다.

“지금 보고 있는 이 페이지 위에 시세가 그냥 떠 있으면 좋겠다”는 생각에서 시작했습니다. 조건은 두 가지였습니다 — 위젯이 일하는 걸 방해하지 않을 것(아래 페이지가 그대로 클릭될 것), 그리고 실제로 실시간일 것(새로고침해야 갱신되는 건 의미가 없음).

How to use

어떻게 쓰나

검색해서 만들고, 원하는 자리에 끌어다 놓으면 끝입니다.

  1. 종목 검색하고 위젯 만들기

    확장 팝업에서 주식 / 코인 모드를 고르고 종목명이나 티커를 검색한 뒤 생성을 누릅니다.

    • 국내주식 — 종목명(삼성전자) 또는 6자리 코드(005930)
    • 해외주식 — 티커.거래소 형식 (AAPL.NAS, NVDA.NYS)
    • 코인 — 심볼 검색 (BTC-USDT)

  2. 페이지 위 원하는 자리에 배치

    웹페이지에서 Shift + 드래그로 위치를 잡습니다. 위젯 우측 핸들을 끌면 폭이, 우하단 핸들을 끌면 전체 크기가 조절됩니다.

    배치한 위젯 아래의 웹페이지는 그대로 클릭됩니다. 시세를 띄워둔 채로 하던 일을 계속할 수 있습니다.

  3. 차트 열어보기

    위젯을 우클릭 → 차트 열기. 직접 만든 캔들 차트가 인라인으로 열립니다.

    • 주기 — 1분 / 15분 / 4시간 / 일 / 주 / 월 (주식은 1분·일·주·월)
    • 지표 — 이동평균(MA 5·10·20·60·120) / EMA / 볼린저밴드 / 거래량
    • 드로잉 — 추세선 · 레이 · 수평선 · 피보나치 되돌림, 자석 스냅
    • 실시간 시세가 캔들에 그대로 반영되고, 크기 조절 가능

  4. 여러 개 다루기

    위젯이 늘어나면 개별로 옮기기 번거로워집니다. 선택 기능으로 묶어서 다룹니다.

    단축키동작
    Shift + 드래그위젯 이동 / 핸들에서 크기 조절
    Cmd·Ctrl + 클릭개별 선택 추가·해제
    Cmd·Ctrl + 드래그빈 공간을 끌어 사각형 범위로 여러 개 선택
    Shift + 드래그 (선택 후)선택된 위젯 그룹 이동
    Shift + Alt + 드래그스냅 끄고 자유 이동
    Delete선택된 위젯 삭제
    Esc선택 해제 / 차트 닫기

  5. 정리하기

    위젯 우클릭으로 한 위젯에 필요한 조작을 모두 꺼냅니다 — 뷰포트에 고정하기, 차트 보기, 평단가 입력, 색상 지정, 숨기기, 삭제.

    팝업에서는 만들어둔 위젯 목록을 보고 위치찾기(해당 위젯으로 스크롤 + 강조), 숨기기/표시, 개별·전체 삭제를 할 수 있습니다. 가격만 크게 보고 싶으면 최소화 모드로 전환합니다.

How it works

어떻게 만들었나

확장은 그리기만 하고, 시세를 다루는 일은 전부 서버로 내렸습니다.

한국투자증권 API     Gate.io API     Binance API
    │ WebSocket        │ WebSocket      │ WebSocket
    └─────────────────┬┴────────────────┘
               ▼
      중계 서버 (Node.js · 의존성 없이 직접 구현)
        · API 키 보관 (확장에 노출 안 됨)
        · 종목 검색 · 스냅샷 조회
        · 구독자 fan-out — 같은 종목은 상류 연결 하나로 공유
        · 경량 프로토콜 v2 — 반복 필드를 걷어내 평균 275B → 65B
               │ WebSocket / SSE
               ▼
      확장 (MV3 content script)
        · Shadow DOM 위젯 렌더링
        · 캔들 차트 엔진
        · 배치·선택·단축키 처리

1. API 키를 확장에 넣을 수는 없다

문제
크롬 확장은 사용자 컴퓨터에 소스가 그대로 설치됩니다. 증권사 API 키를 확장에 넣으면 누구나 꺼내 볼 수 있습니다.
선택
시세 공급자 연결을 통째로 Node.js 중계 서버로 옮겼습니다. 확장은 서버의 API와 실시간 채널만 사용하고, 키는 서버 환경변수에만 존재합니다. 덤으로 같은 종목을 여러 사용자가 봐도 상류 연결은 하나로 두고 fan-out 하게 되어, 증권사 API 호출 수도 줄었습니다.
결과
키가 노출되지 않고, 공급자를 바꿔도 확장은 손대지 않습니다. 실제로 시세 소스 구조를 서버로 옮기는 동안 확장 코드는 그대로였습니다.

2. 로컬에선 압축이 되는데 프로덕션에서만 안 됐다

문제
시세 push 는 clientId(UUID 36B)·종목명·통화·거래소명이 매 틱 반복되는 고중복 JSON입니다. 그래서 WebSocket 표준 압축(permessage-deflate)을 직접 구현해 넣었는데, 로컬과 직결에서는 잘 되면서 프로덕션에서만 대역폭이 줄지 않았습니다. 월 전송량이 27.8GB까지 올라갔습니다.
원인
서버(Render) 앞단의 Cloudflare 가 압축 확장 헤더를 제거하고 있었습니다. 헤더가 사라지면 협상이 성립하지 않고, 구현상 조용히 무압축으로 떨어지도록 되어 있어 에러도 로그도 남지 않았습니다. 제 코드가 아니라 제어할 수 없는 중간 계층이 원인이었습니다.
실패
먼저 만든 건 표준 압축(permessage-deflate)이었습니다. 협상·프레이밍·zlib 문맥 관리까지 직접 구현했고, 통합 테스트도 통과했습니다. 그런데 프로덕션에서만 압축이 걸리지 않았습니다. 핸드셰이크를 찍어보니 이렇게 갈렸습니다.
// 로컬·직결 — 브라우저 제안이 그대로 도착
→ Sec-WebSocket-Extensions:
     permessage-deflate; client_max_window_bits
← Sec-WebSocket-Extensions:
     permessage-deflate; client_no_context_takeover

  negotiate(offer) → { windowBits: 12, ... }
  프레임 RSV1 = 1 → 압축됨

// Cloudflare 뒤 — 제안 헤더 자체가 사라진 채 도착
→ (Sec-WebSocket-Extensions 없음)
← (응답에도 없음)

  negotiate(undefined) → null
  프레임 RSV1 = 0 → 무압축
협상이 성립하지 않으면 무압축으로 조용히 되돌아가도록 설계해 둔 게 여기서 발목을 잡았습니다. 규약상 맞는 처리지만, 그래서 에러도 로그도 남지 않았습니다. 게다가 테스트는 서버에 직접 붙으니 프록시를 통과하는 경로만 검증되지 않았습니다. 그다음으로 "문맥 없이 메시지별로 압축하면?"도 재봤지만, 페이로드가 300B 미만이라 -24.9%에 그쳐 포기했습니다.
선택
프록시가 손댈 수 있는 층(압축 확장)에 의존하지 않고, 건드릴 수 없는 층 — JSON 자체를 줄이기로 했습니다. 구현 전에 scripts/measure-ws-compression.mjs 로 4개 안을 실측해 비교했습니다.
측정
메시지 20,000개 기준        평균 크기      절감
무압축(당시)                  274.8B      기준
독립 압축(문맥 없음)            206.2B     -24.9%
페이로드 다이어트               64.8B     -76.4%
다이어트 + 문맥 유지 압축        20.5B     -92.5%
페이로드가 300B 미만이라 메시지별 독립 압축은 25% 밖에 못 줄입니다. 연결 단위로 압축 문맥을 유지해야(context takeover) 90%대가 나오는데, 그게 바로 프록시에 막힌 방식이었습니다.
구현
프로토콜 v2 — 한 번 받으면 클라이언트가 이미 아는 clientId 를 빼고, 아무도 쓰지 않는 필드를 걷어내고, 종목별로 고정된 통화·거래소명은 바뀔 때만 보냅니다. 시세는 객체 대신 배열 튜플로 보냅니다. 고정값을 생략하니 인코더가 연결별 캐시를 갖게 되어, 클라이언트도 같은 캐시로 빠진 필드를 복원합니다. 이미 배포된 구버전 확장이 깨지지 않도록 ?pv= 버전 협상을 두고, 요청이 없으면 v1 그대로 응답합니다.
예시
삼성전자 시세 한 틱이 실제로 이렇게 바뀝니다.
// v1 — 274B
{"event":"quote","payload":{
  // UUID 36B, 매 틱 반복 — 클라가 이미 안다
  "clientId":"6f1d2c4a-9b3e-4f70-8a21-5c7e93d0b8f1",
  "quotes":[{
    "symbol":"005930",
    "shortName":"삼성전자",       // 안 쓰는 필드
    "price":71200,
    "change":1200,
    "changePercent":1.71,
    // 심볼당 고정값 — 바뀔 때만 보내면 된다
    "currency":"KRW",
    "exchangeName":"KRX",
    "marketState":"TRADING",     // 안 쓰는 필드
    "updatedAt":1742188800000
  }]
}}

// v2 — 56B
{"e":"q","p":[["005930",71200,1200,1.71,1742188800000]]}
//  e = 이벤트("q" = quote)
//  p = [[심볼, 현재가, 등락, 등락률, 시각]]
274B → 56B (-79.6%) — 같은 정보를 그대로 복원할 수 있습니다. clientId 는 연결 시 ready 로 한 번 받아 클라이언트가 이미 알고, 통화·거래소명은 바뀔 때만 튜플 끝에 붙습니다. 첫 전송과 재연결 직후에는 ["KRW","KRX"] 가 실려 70B가 되고, 그걸로 클라이언트 캐시를 세웁니다.
결과
평균 274.8B → 64.8B (-76.4%), 월 전송량 27.8GB → 6.5GB로 과금 구간을 벗어났습니다. 압축 구현은 그대로 남겨 뒀습니다 — 프록시를 거치지 않는 경로에서는 두 절감이 함께 걸려 -92.5%가 됩니다. 인프라가 협조하지 않아도 확보되는 하한선을 갖게 된 셈입니다.

3. 위젯이 페이지를 가로막지 않게

문제
페이지 위에 요소를 띄우면 그 아래 링크·버튼이 클릭되지 않습니다. 시세를 보려고 일을 못 하게 되면 안 됩니다. 게다가 남의 사이트 CSS가 위젯 스타일을 덮어쓰는 문제도 있었습니다.
선택
Shadow DOM으로 스타일을 격리해 어떤 사이트에서도 위젯이 동일하게 보이게 하고, pointer-events를 조정해 위젯 영역의 클릭이 아래 페이지로 통과하도록 했습니다. 배경색 대비도 자동 보정해 밝은 사이트든 어두운 사이트든 읽히게 했습니다.
결과
시세를 띄워둔 채로 원래 하던 일을 그대로 할 수 있습니다.

4. 단축키가 브라우저 기본 동작과 충돌했다

문제
초기 설계에서 Shift + 드래그를 사각형 범위 선택에 썼는데, 이게 브라우저 기본 동작인 텍스트 범위 선택과 충돌했습니다. 대안으로 넣은 Cmd + 클릭 개별 선택은 클릭 통과를 위해 걸어둔 pointer-events: none 때문에 아예 동작하지 않았습니다. 2번에서 얻은 장점이 그대로 부작용이 된 셈입니다.
선택
단축키 체계를 재설계했습니다. 범위 선택을 Cmd·Ctrl + 드래그로 옮겨 텍스트 선택과의 충돌을 없애고, Shift + 드래그는 이동·크기 조절 전용으로 정리했습니다. pointer-events 처리도 고쳐 개별 선택이 정상 동작하게 했습니다.
결과
선택·이동·그룹 이동이 브라우저 기본 동작과 부딪히지 않고 자연스럽게 갈라집니다. (v3.4.2)

5. 시세가 옛날 값에 멈춰 있었다

문제
노트북을 덮었다 열거나, 와이파이가 바뀌거나, 서버가 재시작되면 시세가 갱신을 멈추고 옛 값에 그대로 머물러 있었습니다. WebSocket이 끊겼는데 양쪽 다 끊긴 줄 모르는 half-open 상태여서, 오류도 안 나고 재연결도 트리거되지 않았습니다. 가장 위험한 종류의 버그였습니다 — 화면에 숫자가 멀쩡히 떠 있어서 사용자가 틀린 줄 모릅니다.
선택
연결이 살아 있는지를 주기적으로 확인해 half-open을 감지하고, 끊긴 것으로 판단되면 자동 재연결하도록 했습니다.
결과
절전·네트워크 전환·서버 재시작 후에도 스스로 복구합니다. (v3.6.0)

6. 차트를 직접 만든 이유

문제
차트 라이브러리를 넣으면 번들이 커지고, 남의 페이지 위에 얹히는 오버레이 안에서 스타일·이벤트가 충돌하기 쉽습니다. 실시간 시세를 캔들에 밀어 넣는 방식도 라이브러리마다 제약이 달랐습니다.
선택
캔들 차트 엔진을 직접 구현했습니다. 캔들·거래량 렌더링, 주기 전환, 지표(MA·EMA·볼린저밴드), 드로잉 도구(추세선·레이·수평선·피보나치 되돌림)와 자석 스냅까지 만들었습니다. 캔들 몸통·심지·거래량 막대는 픽셀 정렬을 직접 잡아 안티앨리어싱 번짐과 좌우 비대칭을 없앴습니다.
결과
v4.0.2에서 차트를 전체 무료 공개했습니다. 성능·스타일을 오버레이 환경에 맞게 통제할 수 있게 됐습니다.

7. 체감 속도를 만든 3가지

문제
1분봉 → 일봉처럼 주기를 바꿀 때마다 매번 API를 다시 호출하니 로딩 스피너가 뜨고 멈칫했습니다. 차트를 보는 동작은 원래 주기를 여러 번 왕복하는 일인데, 그때마다 기다리게 되니 흐름이 끊겼습니다. 반대로 빠르게 연달아 누르면 먼저 보낸 요청이 나중에 도착해 이미 바뀐 화면을 덮어썼습니다 — 일봉을 보고 있는데 갑자기 1분봉이 그려지는 식입니다.
선택
전부 “빠르게 느껴지는가”라는 한 문제인데 층이 달라서, 세 군데에서 나눠 풀었습니다.
  • 이미 본 주기 — 2단 캐시 + stale-while-revalidate. 메모리(Map, LRU 40개) → chrome.storage.local(40키) 순으로 찾고, 전환 시엔 신선도를 따지지 않고 캐시를 먼저 그린 뒤 백그라운드로 재검증합니다. TTL은 주기마다 다르게 뒀습니다 — 1분봉 30초, 15분봉 5분, 4시간봉 30분, 일봉 10분, 주·월봉 1시간. 갱신 주기가 다른 데이터에 같은 TTL을 주면 한쪽은 낭비, 한쪽은 낡기 때문입니다
  • 아직 안 본 주기 — 순차 프리페치. 캐시는 한 번 본 주기만 빨라지니, 처음 열고 다른 주기를 누르면 여전히 기다려야 했습니다. 차트를 연 뒤 1.2초 후부터 나머지 주기를 300ms 간격으로 미리 채웁니다. 지연은 첫 화면 렌더와 요청이 겹치지 않게, 순차는 6개를 동시에 던져 API를 때리지 않게 하려는 것입니다. 실패는 무시하고, 차트가 닫히면 즉시 중단합니다
  • 늦게 도착한 응답 — 그냥 버린다. 앞의 둘이 “빠르게 만드는” 쪽이라면 이건 빠른 조작을 견디게 하는 쪽입니다. 그리기 직전에 “지금도 이게 맞나”를 확인하는 가드(stillCurrent())를 둬, 요청 시점의 주기·종목·차트 존재 여부가 하나라도 달라졌으면 렌더를 버립니다. 받아온 데이터는 캐시에 그대로 저장하니 버린 요청도 낭비가 아니고, 차트를 닫은 뒤 도착한 응답이 없는 요소를 건드리던 문제도 같이 사라졌습니다
결과
주기 전환에서 체감 지연이 사라졌고, 캐시가 빈 첫 전환부터 즉시 그려집니다. 아무리 빠르게 눌러도 마지막으로 고른 주기만 화면에 남습니다. 탭을 오래 켜둬도 LRU 상한으로 메모리가 무한히 늘지 않습니다.

8. 과거를 보려면 드래그하다 끝에서 막혔다

문제
차트를 왼쪽으로 끌어 과거를 보다 보면 처음 받아온 구간 끝에서 더 이상 안 갔습니다. 과거를 더 보려면 별도 조작이 필요했는데, 사용자는 그냥 계속 끌고 싶어 합니다.
선택
뷰포트 왼쪽 끝에서 10개 캔들 이내로 접근하면 과거 데이터를 자동 조회해 앞에 이어붙입니다. 여기서 챙긴 것들:
  • 중복 요청 차단 — 엔진·호출부 양쪽에 로딩 플래그를 둬 드래그 중 같은 구간을 여러 번 받지 않게 함
  • 중복 캔들 제거 — 기존 시각을 Set으로 모아 겹치는 캔들을 걸러냄. 경계에서 캔들이 겹쳐 들어오면 그래프가 틀어짐
  • 뷰포트 보정 — 앞에 n개를 붙이면 인덱스가 밀리므로 보고 있던 구간을 n만큼 이동시켜 화면이 튀지 않게 함
  • 종료 처리 — 빈 응답이 오면 “더 없음”으로 표시해 이후 요청을 멈춤
  • 타임존 보정 — 분봉은 서버가 UTC 기준이라 조회 기준 시각에 오프셋을 적용
결과
끊김 없이 계속 끌어서 과거를 볼 수 있습니다. 지표와 드로잉도 데이터가 늘어날 때 함께 다시 계산됩니다.

9. 설치 직후, 안내를 띄울 화면 자체가 없었다

문제
이 확장은 보고 있는 페이지 위에 위젯을 얹는 게 전부입니다. 그런데 설치를 마친 직후 사용자가 보고 있는 탭은 대개 크롬 웹스토어이고, 크롬 정책상 스토어와 chrome:// 페이지에는 확장 스크립트가 주입되지 않습니다. 그 화면에서는 위젯도, 안내도 아무것도 뜰 수 없습니다. 설치 → 아무 일도 안 일어남 → 이탈, 이게 획득 단계에서 가장 크게 새는 구멍이었습니다.
선택
설치 시점에 확장이 소유한 페이지(welcome.html)를 직접 열어 착륙 지점을 만들었습니다. 확장 자기 페이지는 주입이 아니라 일반 로드라 정책 제약을 받지 않아서, 여기서 안내를 시작할 수 있습니다. 이어서 팝업 → 실제 웹페이지로 3막에 걸쳐 넘깁니다 — 각 막은 스크립트가 확실히 살아 있는 화면에서만 돕니다.
  • 제약을 숨기지 않았습니다 — 이 페이지에 「여기서는 위젯이 동작하지 않습니다」를 그대로 띄우고, 바로 열 수 있는 일반 페이지 두 개를 버튼으로 줬습니다. 「왜 안 되지」로 이탈하는 것보다 「저기로 가면 된다」가 낫습니다
  • 임의 URL 에 안내를 주입하는 길은 버렸습니다 — 그러려면 <all_urls> 권한을 요청해야 하고, 그러면 설치 화면에 “모든 웹사이트의 데이터를 읽고 변경” 경고가 붙습니다. 획득이 병목인 확장에서 설치 문턱을 높이는 건 남는 장사가 아닙니다
  • 툴바 고정 안내에는 화살표를 쓰지 않았습니다 — 퍼즐 아이콘은 브라우저 UI라 어떤 문서의 DOM 에도 없고, 좌표가 고정 확장 개수·프로필 아바타·창 컨트롤·확대율에 따라 다 움직입니다. 예전엔 innerWidth - 240 을 가리키는 화살표를 뒀는데 대개 프로필 쪽을 찍었습니다. 틀린 화살표는 없는 화살표보다 나쁩니다. 카드를 우상단에 붙여 방향만 전합니다
결과
설치 직후 빈 화면을 보는 경로가 없어졌습니다. 안내는 스크립트가 반드시 동작하는 화면에서만 시작하고, 최초 설치에만 한 번 뜹니다. 이 페이지의 문구도 한국어·영어 모두 _locales에서 옵니다 — 언어에 따라 위키백과 링크까지 각 언어판으로 바뀝니다.

10. 튜토리얼이 사용자 손이 움직이는 중에 넘어갔다

문제
설치 직후 실제 UI 위에 스포트라이트를 띄우는 온보딩 투어를 만들었습니다. “위젯을 끌어서 옮겨 보세요” 처럼 사용자 동작을 기다리는 단계가 있는데, 이걸 pointerdown 이나 폴링으로 판정하면 아직 끌고 있는 중에 다음 단계 문구로 바뀌어 화면이 흔들립니다. 반대로 느슨하게 두면 제자리에서 한 번 클릭만 해도 단계가 넘어가, 배우지 않고 통과합니다.
선택
판정을 손을 뗀 시점(pointerup)으로 옮기고, “실제로 했다”의 기준을 이동량으로 정의했습니다.
  • 이동 6px(맨해튼 거리) 미만은 제자리 클릭으로 보고 넘기지 않음
  • 너비 변화 12px 미만은 크기 조절로 인정하지 않음 — 시세 갱신 리렌더로 생기는 1~2px 흔들림을 조작으로 오인하면 안 됩니다
  • 12초 교착 타이머 — 위젯 상한에 걸려 버튼이 disabled 인 것처럼 조작 자체가 불가능한 상황에서는 아무리 기다려도 조건이 성립하지 않습니다. 일정 시간이 지나면 수동 “다음” 버튼을 열어 갇히지 않게 했습니다
검증
확장을 실제 Chromium 에 로드해 Shift+드래그·마퀴 선택·우클릭까지 재현하는 E2E 를 짰습니다. 중요한 건 음성 검증입니다 — 제자리 클릭이나 4px 리사이즈로는 단계가 넘어가지 않아야 합니다. 성공 경로만 보면 판정이 느슨해지는 회귀를 못 잡습니다.
결과
끌고 있는 동안 화면이 흔들리지 않고, 클릭만으로 단계를 건너뛰는 것도 막혔습니다. 최초 설치에만 자동 실행되고, 다시 보고 싶으면 팝업에서 재생할 수 있습니다.
