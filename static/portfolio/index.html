P1Chrome Extension + Node.js 중계 서버·2026.03 — 진행중 · v4.0.0

stock-price-extension

어떤 웹페이지 위에서든 주식·암호화폐 시세를 실시간으로 띄우는 위젯 오버레이.

실사용자 30명+ 스토어 평점 5.0 자체 캔들 차트 엔진 봉 전환 지연 0

불편했던 점

주식·코인 시세가 수시로 궁금한데, 확인하려면 그때마다 보던 화면을 벗어나 증권사 앱이나 거래소 탭을 따로 열어야 했다. “지금 보고 있는 이 페이지 위에 시세가 그냥 떠 있으면 좋겠다”는 생각에서 시작했다.

해결

  • API를 감싸는 Node.js RESTful 시세 중계 서버를 직접 설계·구현해 키를 서버 뒤로 숨김
  • WebSocket 실시간 스트리밍을 기본으로, 장애 시 REST 폴링으로 자동 전환하는 폴백 구성
  • Shadow DOM으로 CSS를 격리하고, pointer-events로 아래 페이지가 그대로 클릭되게 함
  • 오버레이 환경에 맞춰 캔들 차트 엔진을 직접 구현 — 지표(MA·볼린저밴드), 드로잉(추세선·피보나치)
  • 차트 2단 캐시(LRU+storage)·주기 프리페치로 봉 전환 지연 제거, 드래그 시 과거 데이터 자동 조회

결과

기획·프론트·중계 서버·배포·운영까지 혼자 끌고 가 스토어에 출시. 실사용자 30명+, 평점 5.0을 유지하며 운영 중.

P2npm package · 빌드 플러그인·2026.03 — 진행중 · v0.4.7

react-code-locator

개발 중 React 화면의 UI를 클릭하면 그 컴포넌트의 소스 파일·라인으로 에디터가 바로 열린다.

npm 배포 v0.4.7 빌드툴 5종 지원 Zero dependencies

불편했던 점

화면에서 고칠 부분은 눈에 보이는데, 그게 어느 컴포넌트·어느 파일에서 그려지는지 찾는 게 매번 번거로웠다. 규모가 큰 프로젝트나 남이 짠 코드에서는 텍스트로 검색해가며 한참 헤맸다. 화면을 클릭하면 바로 그 소스로 갔으면 했다.

해결

  • 기존 도구가 의존하던 fiber._debugSource가 React 19에서 사라진 뒤에도 동작하도록, 빌드타임 AST 변환(@babel/parser)으로 소스 위치를 직접 주입 → React 버전과 무관하게 동작
  • unplugin 기반으로 Vite·Webpack·Rollup·esbuild·Rspack 5종 빌드 툴을 단일 코드베이스로 지원
  • Zero dependencies, dev 전용 — 프로덕션 번들에는 전혀 영향이 없도록 설계

결과

빌드 플러그인 하나만 추가하면 되는 형태로 npm에 배포(v0.4.7). 클래스·HOC·styled·중첩 컴포넌트까지 감지 범위를 넓혔고, 동작하지 않는 조건(Turbopack)은 문서에 먼저 밝혔습니다.

custom-tunnel

로컬 개발 서버를 공개 URL로 즉시 열어, 모바일 등 외부 기기에서 빌드·배포 없이 확인한다.

빌드·배포 120초 → 0 실무 적용

불편했던 점

로컬에서 만든 화면을 실제 폰에서 확인하고 싶은데, 그때마다 빌드하고 배포 서버에 올려(약 120초) 폰으로 접속해야 했다. 작은 수정 하나 보려고 2분씩 기다리는 게 반복되니 개발 흐름이 자꾸 끊겼다.

해결

  • WebSocket 기반 리버스 프록시 릴레이 서버를 설계해 HTTP 요청·응답을 중계
  • 모바일 디버깅용 원격 콘솔 로그 전송(로그 레벨 필터)과 QR 접속, HTTPS 터널 지원
  • VSCode 사이드바 대시보드에서 터널 상태를 한눈에 관리

결과

02

일하는 방식

세 프로젝트에서 반복적으로 지킨 원칙들입니다.

  1. 원인 레이어까지 내려간다

    화면에서 시작해도 원인이 프로토콜·서버·빌드 단계에 있으면 그곳까지 내려가 고칩니다. 시세 위젯의 키 노출은 중계 서버로, 소스 탐색은 빌드타임 AST로 해결했습니다.

  2. 재사용 가능한 구조로 남긴다

    한 번 고친 문제는 일회성 패치가 아니라 모듈로 남깁니다. react-code-locator는 하나의 코어를 5종 빌드 툴 어댑터로 확장했습니다.

  3. 배포·운영까지 직접 끌고 간다

    프로토타입에서 멈추지 않습니다. 셋 다 스토어·npm에 실제 배포했고, 시세 위젯은 실사용자와 평점까지 관리하며 운영 중입니다.

  4. 도구는 쓰는 사람 자리에 둔다

    기능이 아무리 좋아도 쓰러 가야 하면 안 씁니다. 시세는 보던 페이지 위에, 소스 점프는 화면 우클릭에, 터널은 에디터 사이드바에 뒀습니다. 하던 일을 멈추지 않는 게 기준이었습니다.
