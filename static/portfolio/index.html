02

일하는 방식

네 프로젝트에서 반복적으로 지킨 원칙들입니다.

  1. 원인 레이어까지 내려간다

    화면에서 시작해도 원인이 프로토콜·서버·빌드 단계에 있으면 그곳까지 내려가 고칩니다. 시세 위젯의 대역폭 문제는 프론트가 아니라 프록시가 압축 헤더를 걷어낸 탓이어서 WS 프로토콜을 다시 설계했고, 소스 탐색은 재파싱 대신 컴파일러가 이미 계산한 위치를 가로채는 쪽으로 내려가 해결했습니다.

    터널로 꺼낸 화면이 뜨기는 하는데 일부 기능만 조용히 죽던 문제도 그랬습니다. 제 중계 코드를 의심했지만 원인은 dev 서버가 클라이언트 번들에 자기 주소를 문자열로 구워 넣는 것이어서, 브라우저가 마지막에 실제로 다이얼하는 지점(WebSocket·fetch 등)을 감싸 주소를 런타임에 교정했습니다. Next.js dev 서버의 origin 허용 설정 한 줄을 빼면, 사용자 프로젝트는 건드리지 않습니다.

  2. 재사용 가능한 구조로 남긴다

    한 번 고친 문제는 일회성 패치가 아니라 모듈로 남깁니다. react-code-locator는 훅 하나를 Turbopack까지 6종 번들러의 모듈 해석 지점에 꽂는 구조로 확장했습니다.

  3. 배포·운영까지 직접 끌고 간다

    프로토타입에서 멈추지 않습니다. 시세 위젯은 크롬 웹스토어에, 로케이터는 npm에, 터널은 vsix 패키지로 실제 배포했고, 시세 위젯은 실사용자와 평점까지 관리하며 운영 중입니다.

  4. 도구는 쓰는 사람 자리에 둔다

    기능이 아무리 좋아도 쓰러 가야 하면 안 씁니다. 시세는 보던 페이지 위에, 소스 점프는 화면 우클릭에, 터널은 에디터 사이드바에 뒀습니다. 하던 일을 멈추지 않는 게 기준이었습니다.
