stock-price-extension

▼

어떤 웹페이지 위에서든 주식·암호화폐 시세를 실시간으로 띄우는 위젯 오버레이.

실사용자 30명+ 스토어 평점 5.0
문제
증권사·거래소 API의 키와 인증을 클라이언트(확장)에 그대로 두면 그대로 노출된다. 또 불특정 웹페이지 위에 얹히다 보니 사이트마다 스타일이 깨지고 안 보이는 문제가 있었다.
해결
  • API를 감싸는 Node.js RESTful 시세 중계 서버를 직접 설계·구현해 키를 서버 뒤로 숨김
  • WebSocket 실시간 스트리밍을 기본으로, 장애 시 REST 폴링으로 자동 전환하는 폴백 구성
  • Shadow DOM으로 CSS를 격리하고, 배경색 대비를 자동 보정해 어느 사이트에서든 읽히게 함
결과
기획·프론트·중계 서버·배포·운영까지 혼자 끌고 가 스토어에 출시. 실사용자 30명+, 평점 5.0을 유지하며 운영 중.

react-code-locator

▼

개발 중 React 화면의 UI를 클릭하면 그 컴포넌트의 소스 파일·라인으로 에디터가 바로 열린다.

npm 배포 v0.4.0 빌드툴 5종 지원
문제
기존 도구들은 fiber._debugSource에 의존했는데, 이게 React 19에서 제거되어 더 이상 동작하지 않았다. Babel·DevTools·브라우저 확장을 요구하는 방식도 무거웠다.
해결
  • 빌드타임 AST 변환(Acorn)으로 소스 위치 메타데이터를 주입 → React 버전과 무관하게 동작
  • unplugin 기반으로 Vite·Webpack·Rollup·esbuild·Rspack 5종 빌드 툴을 단일 코드베이스로 지원
  • Zero dependencies, dev 전용 — 프로덕션 번들에는 전혀 영향이 없도록 설계
결과
빌드 플러그인 하나만 추가하면 되는 형태로 npm에 배포(v0.4.0). 약 1,500줄 규모로 유지.

custom-tunnel

▼

로컬 개발 서버를 공개 URL로 즉시 열어, 모바일 등 외부 기기에서 빌드·배포 없이 확인한다.

빌드·배포 120초 → 0 실무 적용
문제
로컬 변경을 실기기(모바일)에서 확인하려면 매번 빌드·배포(약 120초)를 거쳐야 했다. 피드백 루프가 너무 길었다.
해결
  • WebSocket 기반 리버스 프록시 릴레이 서버를 설계해 HTTP 요청·응답을 중계
  • 모바일 디버깅용 원격 콘솔 로그 전송(레벨별 필터)과 QR 접속, HTTPS 터널 지원
  • VSCode 사이드바 대시보드에서 터널 상태를 한눈에 관리
결과
실무에 직접 적용해 빌드·배포 120초 과정을 제거하고 즉시 검증 환경을 구축. VSCode 확장 v2.1.0로 배포.

How I work

일하는 방식

세 프로젝트에서 반복적으로 지킨 원칙들입니다.

01

원인 레이어까지 내려간다

화면에서 시작해도 원인이 프로토콜·서버·빌드 단계에 있으면 그곳까지 내려가 고칩니다. 시세 위젯의 키 노출은 중계 서버로, 소스 탐색은 빌드타임 AST로 해결했습니다.

02

재사용 가능한 구조로 남긴다

한 번 고친 문제는 일회성 패치가 아니라 모듈로 남깁니다. react-code-locator는 하나의 코어를 5종 빌드 툴 어댑터로 확장했습니다.

03

배포·운영까지 직접 끌고 간다

프로토타입에서 멈추지 않습니다. 셋 다 스토어·npm에 실제 배포했고, 시세 위젯은 실사용자와 평점까지 관리하며 운영 중입니다.

04

실시간 데이터 흐름이 공통 기반

세 프로젝트 모두 직접 설계한 Node.js·WebSocket 중계(relay) 서버 위에서 돕니다. 시세·소스맵·터널 — 다루는 데이터만 다를 뿐 구조는 하나로 이어집니다.
