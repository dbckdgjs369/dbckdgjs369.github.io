Stock Price Widget

어떤 웹페이지 위에서든 주식·코인 시세를 실시간으로 띄우는 위젯 오버레이입니다. 위젯 아래 페이지는 그대로 클릭되고, 우클릭 한 번으로 직접 만든 캔들 차트가 열립니다.

스토어 평점 5.0 운영 중 자체 캔들 차트 엔진 캐시·프리페치로 전환 지연 0 국내·해외주식·코인
Chrome 웹스토어 ↗
Why

왜 만들었나

주식·코인 시세가 수시로 궁금한데, 확인하려면 그때마다 보던 화면을 벗어나 증권사 앱이나 거래소 탭을 따로 열어야 했습니다. 돌아오면 하던 일의 맥락이 끊겨 있었습니다.

“지금 보고 있는 이 페이지 위에 시세가 그냥 떠 있으면 좋겠다”는 생각에서 시작했습니다. 조건은 두 가지였습니다 — 위젯이 일하는 걸 방해하지 않을 것(아래 페이지가 그대로 클릭될 것), 그리고 실제로 실시간일 것(새로고침해야 갱신되는 건 의미가 없음).

How to use

어떻게 쓰나

검색해서 만들고, 원하는 자리에 끌어다 놓으면 끝입니다.

  1. 종목 검색하고 위젯 만들기

    확장 팝업에서 주식 / 코인 모드를 고르고 종목명이나 티커를 검색한 뒤 생성을 누릅니다.

    • 국내주식 — 종목명(삼성전자) 또는 6자리 코드(005930)
    • 해외주식 — 티커.거래소 형식 (AAPL.NAS, NVDA.NYS)
    • 코인 — 심볼 검색 (BTC-USDT)

  2. 페이지 위 원하는 자리에 배치

    웹페이지에서 Shift + 드래그로 위치를 잡습니다. 위젯 우측 핸들을 끌면 폭이, 우하단 핸들을 끌면 전체 크기가 조절됩니다.

    배치한 위젯 아래의 웹페이지는 그대로 클릭됩니다. 시세를 띄워둔 채로 하던 일을 계속할 수 있습니다.

  3. 차트 열어보기

    위젯을 우클릭 → 차트 열기. 직접 만든 캔들 차트가 인라인으로 열립니다.

    • 주기 — 1분 / 15분 / 4시간 / 일 / 주 / 월 (주식은 1분·일·주·월)
    • 지표 — 이동평균(MA 5·10·20·60·120) / EMA / 볼린저밴드 / 거래량
    • 드로잉 — 추세선 · 레이 · 수평선 · 피보나치 되돌림, 자석 스냅
    • 실시간 시세가 캔들에 그대로 반영되고, 크기 조절 가능

  4. 여러 개 다루기

    위젯이 늘어나면 개별로 옮기기 번거로워집니다. 선택 기능으로 묶어서 다룹니다.

    단축키동작
    Shift + 드래그위젯 이동 / 핸들에서 크기 조절
    Cmd·Ctrl + 클릭개별 선택 추가·해제
    Cmd·Ctrl + 드래그빈 공간을 끌어 사각형 범위로 여러 개 선택
    Shift + 드래그 (선택 후)선택된 위젯 그룹 이동
    Shift + Alt + 드래그스냅 끄고 자유 이동
    Delete선택된 위젯 삭제
    Esc선택 해제 / 차트 닫기

  5. 정리하기

    위젯 우클릭으로 한 위젯에 필요한 조작을 모두 꺼냅니다 — 뷰포트에 고정하기, 차트 보기, 평단가 입력, 색상 지정, 숨기기, 삭제.

    팝업에서는 만들어둔 위젯 목록을 보고 위치찾기(해당 위젯으로 스크롤 + 강조), 숨기기/표시, 개별·전체 삭제를 할 수 있습니다. 가격만 크게 보고 싶으면 최소화 모드로 전환합니다.

How it works

어떻게 만들었나

확장은 그리기만 하고, 시세를 다루는 일은 전부 서버로 내렸습니다.

한국투자증권 API        Gate.io API
    │ WebSocket            │ WebSocket
    └──────────┬───────────┘
               ▼
      중계 서버 (Node.js · 의존성 없이 직접 구현)
        · API 키 보관 (확장에 노출 안 됨)
        · 종목 검색 · 스냅샷 조회
        · 구독자 fan-out — 같은 종목은 상류 연결 하나로 공유
               │ WebSocket / SSE
               ▼
      확장 (MV3 content script)
        · Shadow DOM 위젯 렌더링
        · 캔들 차트 엔진
        · 배치·선택·단축키 처리

1. API 키를 확장에 넣을 수는 없다

문제
크롬 확장은 사용자 컴퓨터에 소스가 그대로 설치됩니다. 증권사 API 키를 확장에 넣으면 누구나 꺼내 볼 수 있습니다.
선택
시세 공급자 연결을 통째로 Node.js 중계 서버로 옮겼습니다. 확장은 서버의 API와 실시간 채널만 사용하고, 키는 서버 환경변수에만 존재합니다. 덤으로 같은 종목을 여러 사용자가 봐도 상류 연결은 하나로 두고 fan-out 하게 되어, 증권사 API 호출 수도 줄었습니다.
결과
키가 노출되지 않고, 공급자를 바꿔도 확장은 손대지 않습니다. 실제로 시세 소스 구조를 서버로 옮기는 동안 확장 코드는 그대로였습니다.

2. 위젯이 페이지를 가로막지 않게

문제
페이지 위에 요소를 띄우면 그 아래 링크·버튼이 클릭되지 않습니다. 시세를 보려고 일을 못 하게 되면 안 됩니다. 게다가 남의 사이트 CSS가 위젯 스타일을 덮어쓰는 문제도 있었습니다.
선택
Shadow DOM으로 스타일을 격리해 어떤 사이트에서도 위젯이 동일하게 보이게 하고, pointer-events를 조정해 위젯 영역의 클릭이 아래 페이지로 통과하도록 했습니다. 배경색 대비도 자동 보정해 밝은 사이트든 어두운 사이트든 읽히게 했습니다.
결과
시세를 띄워둔 채로 원래 하던 일을 그대로 할 수 있습니다.

3. 단축키가 브라우저 기본 동작과 충돌했다

문제
초기 설계에서 Shift + 드래그를 사각형 범위 선택에 썼는데, 이게 브라우저 기본 동작인 텍스트 범위 선택과 충돌했습니다. 대안으로 넣은 Cmd + 클릭 개별 선택은 클릭 통과를 위해 걸어둔 pointer-events: none 때문에 아예 동작하지 않았습니다. 2번에서 얻은 장점이 그대로 부작용이 된 셈입니다.
선택
단축키 체계를 재설계했습니다. 범위 선택을 Cmd·Ctrl + 드래그로 옮겨 텍스트 선택과의 충돌을 없애고, Shift + 드래그는 이동·크기 조절 전용으로 정리했습니다. pointer-events 처리도 고쳐 개별 선택이 정상 동작하게 했습니다.
결과
선택·이동·그룹 이동이 브라우저 기본 동작과 부딪히지 않고 자연스럽게 갈라집니다. (v3.4.2)

4. 시세가 옛날 값에 멈춰 있었다

문제
노트북을 덮었다 열거나, 와이파이가 바뀌거나, 서버가 재시작되면 시세가 갱신을 멈추고 옛 값에 그대로 머물러 있었습니다. WebSocket이 끊겼는데 양쪽 다 끊긴 줄 모르는 half-open 상태여서, 오류도 안 나고 재연결도 트리거되지 않았습니다. 가장 위험한 종류의 버그였습니다 — 화면에 숫자가 멀쩡히 떠 있어서 사용자가 틀린 줄 모릅니다.
선택
연결이 살아 있는지를 주기적으로 확인해 half-open을 감지하고, 끊긴 것으로 판단되면 자동 재연결하도록 했습니다.
결과
절전·네트워크 전환·서버 재시작 후에도 스스로 복구합니다. (v3.6.0)

5. 차트를 직접 만든 이유

문제
차트 라이브러리를 넣으면 번들이 커지고, 남의 페이지 위에 얹히는 오버레이 안에서 스타일·이벤트가 충돌하기 쉽습니다. 실시간 시세를 캔들에 밀어 넣는 방식도 라이브러리마다 제약이 달랐습니다.
선택
캔들 차트 엔진을 직접 구현했습니다. 캔들·거래량 렌더링, 주기 전환, 지표(MA·EMA·볼린저밴드), 드로잉 도구(추세선·레이·수평선·피보나치 되돌림)와 자석 스냅까지 만들었습니다. 캔들 몸통·심지·거래량 막대는 픽셀 정렬을 직접 잡아 안티앨리어싱 번짐과 좌우 비대칭을 없앴습니다.
결과
v4.0.0에서 차트를 전체 무료 공개했습니다. 성능·스타일을 오버레이 환경에 맞게 통제할 수 있게 됐습니다.

6. 주기를 바꿀 때마다 로딩이 보였다

문제
1분봉 → 일봉처럼 주기를 바꿀 때마다 매번 API를 다시 호출하니 로딩 스피너가 뜨고 멈칫했습니다. 차트를 보는 동작은 원래 주기를 여러 번 왕복하는 일인데, 그때마다 기다리게 되니 흐름이 끊겼습니다.
선택
2단 캐시 + stale-while-revalidate로 바꿨습니다. 메모리(Map, LRU 40개) → chrome.storage.local(40키) 순으로 찾고, 전환 시엔 신선도를 따지지 않고 캐시를 먼저 그린 뒤 백그라운드로 재검증합니다. TTL은 주기마다 다르게 뒀습니다 — 1분봉 30초, 15분봉 5분, 4시간봉 30분, 일봉 10분, 주·월봉 1시간. 갱신 주기가 다른 데이터에 같은 TTL을 주면 한쪽은 낭비, 한쪽은 낡기 때문입니다.
결과
주기 전환에서 체감 지연이 사라졌습니다. 탭을 오래 켜둬도 LRU 상한으로 메모리가 무한히 늘지 않습니다.

7. 첫 전환은 여전히 느렸다

문제
캐시는 한 번 본 주기만 빨라집니다. 차트를 처음 열고 다른 주기를 누르면 캐시가 비어 있어 결국 기다려야 했습니다.
선택
차트를 연 뒤 1.2초 후부터 나머지 주기를 300ms 간격으로 순차 프리페치해 캐시를 미리 채웁니다. 지연을 준 건 첫 화면 렌더와 요청이 겹치지 않게 하려는 것이고, 순차로 돌린 건 6개를 동시에 던져 API를 때리지 않으려는 것입니다. 실패는 무시하고 넘어가며, 차트가 닫히면 즉시 중단합니다.
결과
첫 전환부터 즉시 그려집니다. 캐시가 신선하면 프리페치도 건너뜁니다.

8. 응답이 늦게 도착해 엉뚱한 차트를 덮었다

문제
주기를 빠르게 연달아 누르면, 먼저 보낸 요청이 나중에 도착해 이미 바뀐 화면을 덮어썼습니다. 일봉을 보고 있는데 갑자기 1분봉이 그려지는 식입니다. 차트를 닫은 뒤 응답이 와서 없는 요소를 건드리는 경우도 있었습니다.
선택
응답을 그리기 직전에 “지금도 이게 맞나”를 확인하는 가드(stillCurrent())를 뒀습니다. 요청 시점의 주기·종목·차트 존재 여부를 응답 시점과 비교해, 하나라도 달라졌으면 렌더를 버립니다. 데이터는 캐시에 그대로 저장하니 버린 요청도 낭비가 아닙니다.
결과
아무리 빠르게 눌러도 마지막으로 고른 주기만 화면에 남습니다.

9. 과거를 보려면 드래그하다 끝에서 막혔다

문제
차트를 왼쪽으로 끌어 과거를 보다 보면 처음 받아온 구간 끝에서 더 이상 안 갔습니다. 과거를 더 보려면 별도 조작이 필요했는데, 사용자는 그냥 계속 끌고 싶어 합니다.
선택
뷰포트 왼쪽 끝에서 10개 캔들 이내로 접근하면 과거 데이터를 자동 조회해 앞에 이어붙입니다. 여기서 챙긴 것들:
  • 중복 요청 차단 — 엔진·호출부 양쪽에 로딩 플래그를 둬 드래그 중 같은 구간을 여러 번 받지 않게 함
  • 중복 캔들 제거 — 기존 시각을 Set으로 모아 겹치는 캔들을 걸러냄. 경계에서 캔들이 겹쳐 들어오면 그래프가 틀어짐
  • 뷰포트 보정 — 앞에 n개를 붙이면 인덱스가 밀리므로 보고 있던 구간을 n만큼 이동시켜 화면이 튀지 않게 함
  • 종료 처리 — 빈 응답이 오면 “더 없음”으로 표시해 이후 요청을 멈춤
  • 타임존 보정 — 분봉은 서버가 UTC 기준이라 조회 기준 시각에 오프셋을 적용
